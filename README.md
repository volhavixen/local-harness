# Local Harness для Codex

Универсальные правила работы с задачами: планирование, проверка исходного поведения, минимальное изменение, применимые проверки и доказательный отчёт. Runtime и команды выбираются по проекту. Конкретные модели, режим Plan/Default, рабочая папка и личные предпочтения не навязываются базовой установкой.

## Благодарность

Отдельная благодарность [belkovrv](https://gitlab.com/belkovrv).

## Что входит

- [AGENTS.md](AGENTS.md) — универсальные инструкции, необходимые связанным процедурам skill.
- [skills/local-harness/SKILL.md](skills/local-harness/SKILL.md) — skill, критерии существенности S1–S7 и применимости проверок T1–T6, дополнительные процедуры и шаблоны.
- `skills/local-harness/scripts/check.py` — необязательный helper записи команды, версии, лога и результата.
- [tools/resource-queue/README.md](tools/resource-queue/README.md) — необязательная общая очередь тяжёлых проверок и браузерных сценариев для macOS/Linux/WSL.
- [examples/personal-preferences.md](examples/personal-preferences.md) — отдельный необязательный пример личных настроек. Он не устанавливается и не подключается автоматически.

## Установка на macOS

Откройте Codex и отправьте сообщение — вручную копировать файлы не потребуется:

> Установи универсальный harness из https://github.com/volhavixen/local-harness на macOS по README. Определи фактические каталоги Codex и моих проектов, сохрани копии текущих правил и skill, объедини базовые инструкции с моими без потери требований. Личные настройки из examples не устанавливай. Модели, Plan/Default и настройки приложения не меняй. Уточни, нужна ли мне необязательная общая очередь проверок; если нужна, настрой один общий экземпляр. Проверь установку и сообщи результат.

Базовые правила и шаблоны не требуют Python. Для helper нужен Python 3.9+; `check.py` и очередь используют стандартную библиотеку, PyYAML им не нужен. Для клонирования нужен Git; недостающие инструменты устанавливаются отдельно с учётом разрешений пользователя.

## Установка на Windows

### Нативная Windows — базовый harness

Можно установить правила, skill и необязательный `check.py`. Встроенная очередь нативно не работает: `heavy_check.py` использует POSIX-модуль `fcntl`. Поэтому этот вариант не предоставляет автоматическую общую блокировку тяжёлых проверок; запуски между чатами нужно согласовывать последовательно.

Откройте Codex в Windows и отправьте:

> Установи универсальный harness из https://github.com/volhavixen/local-harness для нативной Windows по README. Определи фактический каталог Codex и доступный Python, сохрани копии текущих правил и skill, объедини только базовые инструкции. Личные настройки из examples не устанавливай, модели и настройки приложения не меняй. POSIX-очередь не устанавливай и не запускай; запиши согласованный последовательный порядок тяжёлых проверок и отсутствие автоматической общей блокировки. Если Python доступен, проверь check.py; иначе укажи, что установлен только набор правил и шаблонов.

Для `check.py` нужен Python 3.9+. Права 0600/0700 не гарантируют Windows ACL; при отмене используется завершение дочернего процесса без POSIX-гарантии остановки всей его группы. Эти ограничения не устраняются сменой синтаксиса команды на PowerShell. Фактическое выполнение helper в Windows при подготовке этого репозитория не проверялось.

### Windows через WSL — вариант с очередью

Для использования поставляемой очереди можно выбрать WSL. Если WSL ещё не установлен, следуйте [инструкции Microsoft](https://learn.microsoft.com/en-us/windows/wsl/install): для поддерживаемых версий Windows команда `wsl --install` выполняется в PowerShell от администратора, затем требуется перезагрузка. Установка WSL и инструментов внутри него — отдельное действие пользователя; harness не выполняет её автоматически.

Используйте экземпляр Codex, который действительно выполняется внутри выбранного WSL-дистрибутива и читает его Linux-каталог skills. Открытая WSL-вкладка терминала внутри Windows-приложения сама по себе этого не подтверждает. Если Codex работает только в Windows, выберите базовую установку выше либо отдельно настройте доступный способ запуска Codex в WSL. В экземпляре Codex внутри WSL отправьте:

> Установи универсальный harness из https://github.com/volhavixen/local-harness внутри текущего WSL-дистрибутива по README. Используй Linux-пути и Linux Python, определи каталог этой установки Codex, сохрани копии моих правил и skill. Личные настройки из examples и настройки моделей не применяй. Настрой один общий экземпляр очереди для согласованных чатов в этой WSL-среде и проверь установку. Не смешивай его с Windows Python или отдельной Windows-копией Codex.

Codex, Python, helper и команды проверок должны выполняться в согласованной WSL-среде. Windows и WSL имеют разные домашние каталоги и могут использовать разные установки Codex; установка в одном окружении не означает установку в другом. Блокировка WSL не перехватывает Windows-команды и запуски других несогласованных окружений. При их совместной работе требуется отдельная координация. Проверка на настоящей WSL-машине при подготовке этой версии не выполнялась.

## Что делает установка

1. Скачивает репозиторий в разрешённую рабочую папку. Конкретное имя и расположение папки базовым harness не задаются.
2. Определяет фактический каталог данных Codex (учитывая настроенный `CODEX_HOME`). `~/.codex` — пример распространённого расположения, а не обязательный путь. Для Windows и WSL расположения определяются отдельно.
3. Сохраняет резервные копии существующих правил и skill, согласует конфликты и объединяет корневой `AGENTS.md` с постоянными инструкциями Codex. Сам каталог Codex и конфигурация приложения не перемещаются.
4. Размещает `skills/local-harness/` в каталоге skills той же установки. Сохраняет структуру `AGENTS.md` рядом с `skills/`, поскольку skill ссылается на общие правила относительными путями.
5. При выбранной POSIX-очереди размещает один экземпляр helper в согласованном месте и записывает абсолютный путь в локальные инструкции. Перед запуском задаёт `HARNESS_QUEUE` в окружении команды; на переменную из другой terminal-session полагаться нельзя. Если очередь уже есть, использует её прежний путь и каталог state. Перед заменой helper дожидается свободного состояния через `--status`, включая завершение screen-брони владельцем; активный helper/state не перемещает и новую копию очереди не создаёт. Очереди для отдельных проектов не создаёт.
6. Проверяет доступность файлов, ссылок и запуска выбранных helper. Пример личных настроек не копирует и не подключает. Глобальная установка действует на последующие задачи, поэтому сохраняются действующие ограничения пользователя и команды.

Для ручного скачивания, если оно нужно: выполните `git clone https://github.com/volhavixen/local-harness.git` в выбранной рабочей папке. Затем используйте порядок выше; существующий `AGENTS.md` целиком не перезаписывайте.

## Проверка установки и начало работы

На macOS/Linux/WSL, если используется стандартный каталог Codex:

```sh
python3 "$HOME/.codex/skills/local-harness/scripts/check.py" --help
```

На нативной Windows с установленным Python Launcher и стандартным каталогом Codex, в PowerShell:

```powershell
py -3 "$env:USERPROFILE\.codex\skills\local-harness\scripts\check.py" --help
```

Если каталог Codex или исполняемый файл Python отличается, установщик подставляет фактический путь. Примеры не устанавливают Python и не подтверждают доступность launcher.

Для выбранной очереди на macOS/Linux/WSL:

```sh
export HARNESS_QUEUE="/absolute/path/to/resource-queue/heavy_check.py"
python3 "$HARNESS_QUEUE" --help
```

Замените пример на реальный абсолютный путь. Перед тяжёлыми запусками прочитайте руководство очереди. Этот helper поддерживает 1 или 2 worker и по умолчанию использует 1; для других систем ограничения определяются по проекту и ресурсам. Очередь не разрешает E2E сама по себе.

После установки откройте новый чат и дайте обычную задачу — harness подключается через установленные постоянные инструкции. Для явного вызова: **«Примени $local-harness к этой задаче»**. Если skill недоступен, проверьте каталог текущей установки и ссылки; наличие файлов само по себе не доказывает их подключение.

## Личные настройки — отдельно

[Пример личных предпочтений](examples/personal-preferences.md) содержит выбор моделей, режимы, рабочую папку, ограничения ресурсов и стиль общения автора. Базовый harness не требует его чтения. Чтобы воспользоваться примером, выберите только нужные пункты и явно добавьте их в свои инструкции. Пример сам не выдаёт разрешений на делегирование, публикацию или изменение конфигурации. Значения путей в примере нужно адаптировать до применения; в TOML использовать фактический абсолютный путь, а не рассчитывать на раскрытие `~`.

Универсальная часть сохраняет требования к качеству: действующие правила проекта, применимые проверки, честные статусы, воспроизводимые доказательства, сравнение намерения с результатом и уборку собственных временных ресурсов. Конкретный набор, запреты E2E и условия CI задаются проектом и поручением.

## Границы публикации

В репозитории нет частных проектных инструкций, истории задач, логов, баз, env, ключей и активного состояния очереди. Исполняемые helper не изменялись при отделении личных настроек. Установленная личная копия автора этой доработкой не обновляется. Шаблоны assets содержат ссылки на публичные процедуры GitHub; для автономной работы их можно заменить путями своей установленной копии.
