# Local Harness для Codex

Личные правила работы с Codex: планирование, выполнение задачи, проверяемые результаты, локальное ревью и подготовка ручной приёмки. Публичная версия актуального harness от 22 ноября 2026 года.

## Благодарность

Отдельная благодарность [belkovrv](https://gitlab.com/belkovrv).

## Что входит

- [AGENTS.md](AGENTS.md) — постоянные инструкции: рабочий процесс, модели, размещение проектов, ресурсы, доказательства, исправление расхождений и правила взаимодействия.
- [skills/local-harness/SKILL.md](skills/local-harness/SKILL.md) — основной skill и маршрутизация к нужным процедурам.
- `skills/local-harness/references/` — критерии существенности S1–S7, применимость этапов T1–T6, пограничные случаи, доказательства, изолированное ревью, ручная приёмка, совместимость данных и измерения производительности.
- `skills/local-harness/assets/` — шаблоны состояния задачи и итогового отчёта.
- `skills/local-harness/scripts/check.py` — необязательная запись команды, лога, версии исходников и результата.
- [tools/resource-queue/README.md](tools/resource-queue/README.md) — общая очередь тяжёлых локальных проверок и браузерных сценариев; рядом helper и самотесты.

## Установка

Требуются Codex и Python 3.9+ для helper. Helper используют стандартную библиотеку; PyYAML им не нужен. Очередь использует POSIX `fcntl` и предназначена для macOS/Linux. Нативная Windows требует отдельной адаптации.

### Через сообщение Codex

Откройте Codex и отправьте сообщение — копировать файлы вручную не потребуется:

> Установи harness из https://github.com/volhavixen/local-harness по подробной инструкции установки в README. Сохрани копии моих текущих правил, адаптируй пути под мой компьютер и согласуй изменения существующих настроек. Проверь установку и сообщи результат.

После установки откройте новый чат и дайте обычную задачу — harness будет подключаться автоматически через постоянные инструкции. Для явного вызова можно написать: **«Примени $local-harness к этой задаче»**.

### Подробная установка

1. Клонируйте репозиторий в свою рабочую папку:

   ```sh
   mkdir -p ~/Documents/Work
   git clone https://github.com/volhavixen/local-harness.git ~/Documents/Work/local-harness
   ```

2. Сохраните копии своих существующих `~/.codex/AGENTS.md` и `~/.codex/skills/local-harness`. Прочитайте правила репозитория и объедините их со своими инструкциями. Содержимое корневого `AGENTS.md` предназначено для установки в `~/.codex/AGENTS.md`; относительные ссылки в нём рассчитаны на это расположение и на структуру данного репозитория.
3. Скопируйте `skills/local-harness/` в `~/.codex/skills/local-harness/`. Сохраните структуру: skill зависит от согласованных правил в `~/.codex/AGENTS.md`.
4. Разместите `tools/resource-queue/` в `~/Documents/Work/CodexTools/resource-queue/`. Используйте один экземпляр очереди для всех проектов и чатов компьютера. Если очередь уже работает, согласуйте обновление, сохраните её состояние и дождитесь завершения текущих запусков; не удаляйте активную блокировку.
5. Выберите свою рабочую папку. В устанавливаемых инструкциях и документации замените `~/Documents/Work` на фактический абсолютный путь этой папки, а `~/.codex` — на фактический путь используемой установки Codex, где необходим абсолютный путь. Особенно это касается значения `projectlessWorkspaceRoot` в конфигурации: не полагайтесь на раскрытие `~` внутри TOML. Репозиторий сам не меняет конфигурацию приложения.
6. Проверьте персональные предпочтения: Plan/Default, модели, разрешения на делегирование и обязательность этапов. Это исходные предпочтения автора, а не требования Codex ко всем проектам. Применяйте согласованный вариант, сохраняя более приоритетные правила своей команды и проекта.
7. Откройте новый чат. В постоянных инструкциях задано автоматическое подключение harness; явный вызов для проверки: «Примени $local-harness к этой задаче».

Шаблоны `assets/` содержат ссылки на публичные процедуры GitHub: они остаются доступны после копирования шаблона во внешний каталог задачи. Для автономной работы их можно заменить абсолютными путями своей установленной копии.

## Проверка установки

```sh
python3 ~/.codex/skills/local-harness/scripts/check.py --help
python3 ~/Documents/Work/CodexTools/resource-queue/heavy_check.py --help
```

Перед тяжёлыми командами прочитайте руководство очереди. По умолчанию используется один worker; второй допустим по условиям правил. Очередь не разрешает E2E сама по себе и не перехватывает команды, запущенные в обход helper. Ограничения E2E и CI определяются действующими правилами конкретного проекта.

Основные процедуры: требования → исходный сценарий → минимальное изменение → применимые проверки → исправление подтверждённых ошибок → проверка итоговой версии → доказательный отчёт. Пропущенные и незапущенные проверки не превращаются в PASS. Изменение инструкции само по себе не доказывает изменение поведения агента.

## Границы публикации

В этой версии локальные пути автора заменены переносимыми примерами. Частные инструкции CRM не включены. Исходные helper опубликованы без изменения логики. История задач, логи, скриншоты, базы, env, ключи, активные брони и состояние очереди не публикуются. Установка и копирование правил сами по себе не дают разрешения на push, merge, публикацию или внешние сообщения.
