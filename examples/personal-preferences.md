# Необязательный пример личных предпочтений

Этот файл не подключается автоматически и не входит в базовую установку. Это пример настроек автора, а не требования harness. Выберите только нужные пункты, адаптируйте пути и согласуйте их с действующими правилами. Копирование примера не выдаёт разрешений на действия и не переключает режим или модель.

## Режим и модели


- По умолчанию использовать agentic workflow: план → выполнение согласованной задачи → применимые проверки → исправление подтверждённых ошибок → повторная проверка затронутого до готового результата. Если поручена реализация, не завершать работу одним планом. Этот порядок не отменяет обязательные проверки, ограничения и необходимые разрешения.
- Планирование обязательно в начале каждой новой задачи без напоминания пользователя: до реализации составить краткий план, соразмерный задаче. Режим `/plan` использовать, когда он доступен; отсутствие автоматического переключения этого режима не освобождает от планирования. Явное указание пользователя работать иначе имеет приоритет.
- Перед началом новой задачи проверять фактически переданный режим работы. Считать Plan включённым только при явном указании `Collaboration Mode: Plan` в системном контексте. Составление плана текстом не считать включением режима. Если требуется Plan, но фактически передан Default, сразу сообщить о расхождении и не переходить к реализации до настоящего переключения либо прямого разрешения пользователя работать в Default.
- Старшая модель для планирования и координации — Sol 6.1 с уровнем рассуждения High (`gpt-6.1-sol`, `high`).
- Для исполнителей выбирать более младшие доступные модели. Параллельное делегирование независимых подзадач разрешено пользователем без отдельного подтверждения; количество исполнителей выбирать по пользе задачи и фактическим лимитам платформы. Тяжёлые локальные проверки всех исполнителей остаются в одной общей очереди.
- Модели версии 6.2 и модели семейства Astra 6 не запускать без прямого требования пользователя; не выбирать их автоматически для основной работы, исполнителей или замены недоступной модели.
- При запуске skill не добавлять уведомление о невозможности переключить основную модель, включая фразу «Переключить основную модель средствами этого чата я не могу» и её перефразирования. Ограничение переключения сообщать при прямом запросе пользователя на переключение или если оно препятствует выполнению задачи; не выдавать запись предпочтения за фактическое переключение.


## Рабочая папка

Перед применением замените примеры путей на свои. Для `projectlessWorkspaceRoot` в TOML укажите полный абсолютный путь: раскрытие `~` не предполагается. Изменение конфигурации требует отдельного поручения.


- Если пользователь не выбрал существующий проект, создавать новый проект и его рабочую папку ТОЛЬКО внутри `~/Documents/Work`. Это общее правило для всех проектов и чатов Codex.
- Перед созданием проекта, рабочих файлов, результатов или временных материалов проверить фактический абсолютный путь с учётом символических ссылок: он должен находиться внутри `~/Documents/Work/`. Использовать отдельную подпапку задачи; не создавать проект непосредственно в `Documents`, `Documents/Codex`, домашней папке или другом месте за пределами `Work`.
- Автоматически назначенная Codex папка за пределами `Work` не является разрешением работать в ней. До создания файлов выбрать рабочую подпапку внутри `Work` и выполнять работу там. Если переназначить папку средствами приложения нельзя, прямо сообщить об ограничении; не продолжать создавать материалы проекта снаружи.
- Для чатов без проекта сохранять настройку `[desktop].projectlessWorkspaceRoot = "~/Documents/Work"`. Не менять её на другой путь без прямого указания пользователя.
- Существующие явно выбранные проекты использовать по их фактическому расположению. Перенос уже существующих папок выполнять только по отдельному поручению пользователя. Служебные данные самого Codex в `~/.codex` не являются папкой нового проекта.


## Ресурсы и передача результата

- Для ограниченного компьютера: одна общая очередь, 1 worker по умолчанию; максимум 2 при свободных ресурсах. При выборе включённого helper его технический интерфейс также ограничен значениями 1 и 2.
- Пример расположения очереди: `~/Documents/Work/CodexTools/resource-queue/heavy_check.py`; каталог доказательств — `~/Documents/Work/.harness/runs/`. Это примеры, а не обязательные пути.
- Пример рабочего процесса: коллега проводит ревью и merge; исполнитель готовит проверяемый результат. Конкретные действия определяются поручением.
- Для общения с пользователем без технического бэкграунда объяснять простым языком и помогать формулировать требования.

При желании добавьте выбранные предпочтения в свои постоянные инструкции. Разрешение на делегирование, внешние действия и запуск E2E требуется определять отдельно по текущей задаче.
