# Изоляция рабочей копии

Фиксировать MR/PR head, diff base и текущий target отдельно. Чтение старого pipeline
относится к его SHA; head pipeline не означает merged-result с текущим main.
Перед итогом повторно сверить head. Смена версии не обесценивает старые логи,
но требует новой проверки релевантного diff.

Для чужого MR с грязной основной копией создать отдельный worktree существующими
средствами. До создания проверить фактическое расположение новой рабочей копии,
временных конфигов и каталогов по
[правилам размещения](../../../AGENTS.md#размещение-проектов-и-материалов).
В начале и конце записать status; без поручения исходники MR не менять,
не stash/reset чужие изменения и не копировать личные конфиги поверх версии коллеги.

В `environment.md` записать:

- рабочую копию, head и использованные инструкции/версии;
- конкретные порт, URL, тестовую DB, auth/cache, dist, временный tsconfig;
- владельца сервера, PID и команду запуска/остановки, время старта;
- какие файлы/данные созданы текущей задачей, что можно очистить;
- используется ли double или реальная внешняя служба.

При занятом порте выбрать другой, не подключаться к случайному серверу и не
останавливать его. Свободность порта при предварительной проверке не гарантирует
успешный bind: проверить запуск и фактический URL. До запуска проверок или
перехода по URL соблюдать [общую очередь и screen-бронь](run-results.md#очередь-тяжёлых-локальных-проверок).

Параметры изоляции брать из этой версии проекта. Для конкретного проекта могут существовать
E2E_PORT, E2E_PGLITE_DIR, E2E_AUTH_DIR, NEXT_DIST_DIR, NEXT_TSCONFIG_PATH; проверить
поддержку перед использованием. Это не универсальный набор переменных.
Временные конфиги отмечать отдельно от кода MR и удалять только свои файлы.
Не вызывать reset тестов на данных dev/stage/production.

На macOS при переносе `TMPDIR` в разрешённую рабочую область выбирать короткий
путь отдельно от глубоко вложенного каталога доказательств: IPC-сокет CLI может
не поместиться. До долгого прогона проверить служебный запуск фактического CLI
проекта. `listen EINVAL` с путём `.pipe` проверять сравнением с коротким `TMPDIR`,
не изменяя тесты и таймауты без установленной причины.

При очистке и передаче сервера соблюдать
[правила владения и завершения ресурсов](../../../AGENTS.md#уборка-собственных-временных-браузеров-и-серверов).
Не выполнять автоматическую очистку чужих worktrees.
